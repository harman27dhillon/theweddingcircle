- Replace the current long, full-width accordion rows with a clean grid of square or near-square buttons with softly rounded corners.
- Use a premium, elegant wedding-app appearance with balanced spacing, subtle borders, restrained shadows, and the existing theme colors.
- Keep button dimensions consistent and text legible.
- Each button must have its own appropriate title and, if suitable, a small existing icon.
- Arrange buttons in a responsive grid: multiple columns on desktop and an appropriate number on mobile.

- Keep all existing permission checks intact.

Include a separate Wedding Bar button as described in Section 4.

4. Add a Dedicated “Wedding Bar” Button to Host Control

Create a new Host Control button named exactly Wedding Bar.

This must open a dedicated configuration panel where authorized hosts and co-hosts can customize the wedding cover bar, regardless of whether the wedding uses a Preset theme or a Classic theme.

A. Change the cover photo

Allow hosts and co-hosts to:

- Upload or select a replacement cover photo using the project's existing image-selection and storage mechanisms.
- Preview the image before applying it.
- Save the new cover photo and see it reflected in the wedding bar.
- Replace the photo again later.

The cover photo must remain customizable independently of the selected theme. Changing the theme must not silently overwrite the host's chosen cover photo.

Preserve existing photo validation, upload limits, storage behavior, and error handling. Do not introduce a new paid storage service or hard-code image URLs.

B. Freely position the couple's names

Allow hosts and co-hosts to reposition the couple's name text anywhere within the wedding bar.

- Provide a straightforward visual positioning interface, preferably drag-and-drop directly on a live preview.
- Keep the names within the wedding-bar boundaries.
- Save horizontal and vertical positions in a responsive way so they remain sensible on mobile and desktop.
- Preserve the existing typography, font choices, colors, text effects, and line breaks unless the host explicitly changes them.
- Do not force names into a fixed left, center, or right alignment.

C. Freely position the wedding date

Provide the same independent positioning controls for the wedding date.

- Hosts and co-hosts must be able to move it anywhere within the wedding bar.
- The date must remain visible and must not be clipped by the bar's edges.
- Save and restore its position correctly.

D. Freely position the wedding location

Provide the same independent positioning controls for the wedding location.

- Hosts and co-hosts must be able to move it anywhere within the wedding bar.
- Keep it independently positionable from the names and date.
- Save and restore its position correctly.

E. Preview, save, and reset

- Show an accurate live preview of the actual wedding bar while editing.
- Make it clear which element is currently selected.
- Provide Save and Cancel controls.
- Provide a reset-to-default-position option for each text element.
- Save the configuration persistently using the project's existing database and API architecture, not just component state or local storage.
- Ensure changes survive refreshes, sign-outs, and visits from other authorized devices.
- Ensure hosts and co-hosts can edit only weddings they are authorized to manage.
- Guests and ordinary members must not be able to modify the cover photo or positioning by calling the API directly.
- If a theme changes, retain the saved cover photo and element positions unless the user explicitly resets them.

Do not implement fake controls or a preview that looks editable but does not save.
