2. Critical: Fix Mobile Chrome Stuck on Sign-In Check

The mobile screenshot shows a nearly blank page displaying:

“The Wedding Circle — Checking who is signed in on this phone.”

The app does not proceed to the landing page. This started after the recent update and appears to affect mobile Chrome.

Investigate the root cause

Inspect the authentication initialization, Firebase setup, session restoration, loading state, routing guards and asynchronous startup logic.

Check for:

- An authentication listener that never resolves or completes.
- A loading state that remains true after initialization.
- A promise that never settles or an exception that is swallowed.
- Firebase initialization or configuration errors.
- A route guard waiting indefinitely for a user profile or developer role.
- A database request blocking initial page rendering.
- Session restoration differences between desktop and mobile Chrome.
- A redirect loop or incorrect handling of a signed-out user.
- Browser storage, cookie or IndexedDB errors.
- An unavailable backend request that prevents the landing page from rendering.

Required behavior

- Initialize authentication safely and consistently.
- Show a loading screen only while the necessary initialization is genuinely pending.
- Handle both authenticated and signed-out users correctly.
- If no user is signed in, proceed to the intended landing or sign-in screen according to the existing app flow.
- If the session check fails, show a recoverable error with a retry option rather than leaving the user on an indefinite loading screen.
- Add appropriate timeouts and cleanup for asynchronous initialization where needed.
- Ensure errors are logged safely for diagnosis without exposing credentials or tokens.
- Do not bypass authentication or grant access to protected pages just to remove the loading screen.
- Do not remove email verification requirements from ordinary users.
- Preserve the separate developer authentication policy and existing permissions.
- Ensure authentication initialization does not block public landing-page content unnecessarily.

Mobile compatibility

Test the deployed site in Android Chrome, including a fresh session, an existing session, a signed-out session and a session with unavailable network access.

Check responsive rendering and JavaScript console/network errors where testing tools permit. If an external Firebase or backend configuration is incorrect, identify it precisely instead of hiding the error.

Do not claim the mobile issue is fixed unless the application has actually progressed beyond the loading screen in a suitable test.
