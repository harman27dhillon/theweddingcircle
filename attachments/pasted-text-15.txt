Profiles must be scoped to the correct wedding.

- Members may view the profiles of other authorized members of the same wedding.
- Guests may edit only their own wedding profile.
- Hosts or co-hosts may remove a guest from a wedding only within their existing authorized powers.
- Hosts must not be able to access unrelated weddings or private account information merely through this feature.
- Maintain server-side authorization and the existing database security policies.
- Do not trust frontend-only permission checks.
- Prevent users from modifying another guest's profile by changing a user ID or wedding ID in a request.
- Follow existing visibility rules for private weddings and invited guests.

If database changes are required, inspect the existing schema and use safe, additive migrations. Do not reset the database or recreate the authentication system.
