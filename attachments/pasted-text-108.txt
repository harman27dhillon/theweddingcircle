- Never enable public R2 access or "r2.dev".

- Never cache unauthorized or expired requests.
- Never expose private media through unsigned URLs.

3. Implement the correct authorized caching behavior

If the current implementation is incorrect, fix it so that:

1. The Worker verifies the signature and authorization before serving an object.
2. Only successfully authorized media responses are eligible for edge caching.
3. Unauthorized requests continue returning HTTP 403 with private/no-store behavior.
4. Missing objects return HTTP 404.
5. Cache keys cannot allow one wedding's private media to be served to another unauthorized user.
6. Cache TTL and invalidation behavior are appropriate for private wedding media.
7. The response exposes reliable cache diagnostics, including Cloudflare cache status where available.

Do not simply add "public" or "s-maxage" headers without verifying the complete security and cache-key design.

4. Fix the CDN connection test

The test must distinguish between:

- Cloudflare API authentication.
- R2 connectivity.
- Worker availability.
- Unauthorized request rejection.
- Valid signed media delivery.
- Edge cache MISS.
- Edge cache HIT.

A 403 from an anonymous request is an expected security result, not proof that CDN delivery is broken.

Use a dedicated, controlled test object or another safe method to test an authorized request twice. Verify whether the second request produces an actual cache HIT. Do not use real private user media as a test object.

If the test cannot verify a cache HIT, report exactly why instead of showing a misleading success or failure.
